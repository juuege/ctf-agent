## 解法路径（Coppersmith-Sudan 2003 列表译码，官方 ex.sage 全量构造）

1. 容量核验——为什么标准译码全不够：单通道 B-W 容量 ⌊(n−k)/2⌋=196 < w=300；Guruswami-Sudan n−√(nk)=520−√66560≈262 < 300；利用共享错误位置的 c=2 B-W 扩展 ⌊c(n−k)/(c+1)⌋=⌊2·392/3⌋=261 < 300——三条路全被 w=300 压死，必须换 CS 2003 论文构造（people.csail.mit.edu/madhu/papers/2003/copper-conf.pdf）
2. 参数与可行性：r=5、l=1090、c=2、ks=[128,128]、t=n−w=220，可行性断言 t > l/r（220 > 218）；行集 Me={[i,e0,e1]: i+128·e0+128·e1 ≤ l} 共 18240 行，列集 Mr={(a,b0,b1): a+b0+b1 < r} 共 35 个单项式 × n=520 → 18200 列，断言 len(Me) ≥ len(Mr)·n（18240 ≥ 18200）成立才可解
3. 齐次线性系统构建：对每个求值点 pt=[alpha, y0, y1] 与每个 (Me 行, Mr 列) 对，取 ff=∏(vs_k + pt_k)^epow_k 在 mono=∏vs^s 处的单项式系数填 A；A 为 GF(521) 上 18240×18200 稠密矩阵（官方 exp 用 multiprocessing 按列块并行构建，cpu_count 分片）
4. 错误位置提取：A.right_kernel() 全核，rk=核矩阵按行求和；位置 i 判定 = rk 在该求值点的整段 Mr 列块全零（零块=噪声点在所有单项式上同时消去）；得到 300 个噪声位置、220 个干净点
5. 密钥恢复：干净点上按通道拆 (i+1, share[2i]) / (i+1, share[2i+1]) 两个 220 点集，各做 PR.lagrange_polynomial 得两条 127 次多项式，系数 bytes 拼接还原 256B key；AES.new(md5(key).digest(), ECB).decrypt(ct) → flag
6. 离线复现：task.py docstring 自含实例（share+ct）+ ex.sage 原样可跑（sage 环境依赖）；远程版需 pwn 交互送回 shares

## 陷阱与备忘

- 单通道译码器（B-W/G-S）容量数学上限低于 w=300，共享错误位置扩展也只到 261——先算容量再选算法，超过后唯一路径是 CS 线性化，不要在 B-W 变体上死磕
- kernel 求和行的位置检测按 Mr 列块整体判零，不是逐点残差；块宽 |Mr|=35，循环写法 `for ei in range(n): for i in range(len(Mr))` 带 for-else
- r 与 l 必须满足 t > l/r：l 太小丢解、太大矩阵行数爆炸；r=5/l=1090/t=220 是官方调好的可行点
- 解出的 key 是两半段拼接（bytes(poly1)+bytes(poly2)），AES 密钥是 md5(key) 32B 而非 key 本身
- 矩阵必须建在 GF(521) 上（ZZ 上 right_kernel 无解/维度错误）；18240×18200 稠密阵单进程慢，列块并行是工程必需
- 引擎边界：本题需要 sage + 远程交互，属 deploy 类如实未解；本卡为 learn-only 知识面，不进检测器（chain entry 82 裁定：数学译码 fastpath 不占检测器槽位，等第二次同族标本再现再议 derived-evidence arm）
