## 解题链（实证）
1. bsdtar（Windows 自带 tar.exe，libarchive）解 RAR5 → firmware.bin + flag.enc。
2. firmware.bin 魔数 1f8b → gunzip 得 firmware.squashfs（hsqs，squashfs 4.0，gzip 压缩，仅 565B 有效数据）。
3. 本机无 unsquashfs、tar 不识别 squashfs → 纯 stdlib 解析：superblock（inode_tab=305/dir_tab=397/frag_tab=506）→ u16 长度头+zlib 元数据块 → inode/目录/片段表三步提取，命中 config.json。
4. config.json 内硬编码 `aes_key_hex: A1B2C3D4E5F67890ABCDEF1234567890`（另含 MQTT 弱口令 P@ssw0rd_2024，干扰项）。
5. flag.enc 三连解密：ECB ✗ → CBC-零IV ✗ → **CBC-IV前缀 ✓**（首块 16B 为 IV，剩 32B 密文）→ flag。

## 失败与坑
- Invoke-RestMethod 把 blobs API 二进制响应当字符串返回 → 改 Invoke-WebRequest -OutFile。
- zlib.decompress 误用 wbits=16+MAX_WBITS（按 gzip）→ 元数据实为 zlib 格式，默认 wbits 即可。
- 该 squashfs 为手工定制镜像：文件 inode 无 block_list（全走 fragment）、元数据压缩标志位与标准不符 → 按实测字段解析，不迷信规范。
