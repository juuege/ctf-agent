## 漏洞与利用链

- **漏洞**: VM 的 LD/ST 地址为 16 位，但边界检查只比较地址**低字节**与 `.data@0x4010` 的 size 字节(0xff)，高 8 位未检 → mem（run 栈上 0x100 字节）上方 64KB 任意读写
- **无输出原语 → 全寄存器内计算**：LD main 返回地址（libc+0x29d90 锚）→ LD code+0x100 处自藏 delta 常量 → ADD 算出 pop_rdi//bin/sh/ret/system 绝对地址 → ST 写 ROP 链于 mem+0xd38..0xd50 → LD run 返回地址（PIE 锚）加 delta 指向 leave;ret 栈迁移 → ST 回写 mem+0x118 → 非法操作码退出 VM → ret 触发迁移 → `system("/bin/sh")`
- **保护**: PIE+NX+Full RELRO+Canary 全绕过（全程不碰 canary、地址全相对计算）

## 每题一得

VM ALU 第二操作数在 **bits16-20**（`shr eax,0x10`），被我误读为 bits10-14 → 所有 ADD 成 no-op → 写回原值 rc=0 假象，耗掉约 30 分钟。教训：**VM 指令编码必须逐字段对 ASM 核对位移量（0x10≠10）**。

## 题解学习要点（官方 WP: cnblogs seyedog）

- 官方更简（4 指令 vs 我 18）：锚用 mem+0xa40 的 **ld.so 栈残留 _dl_fini 指针**，delta = onegadget - _dl_fini 偏移，SUB 后直接 STR one_gadget 到 [0x118]，无栈迁移无 ROP 链
- 新知：初始未初始化栈含 ld.so 残留函数指针可作 libc 锚；one_gadget 约束（rsp&0xf==0 等）在 VM 退出路径常天然满足
