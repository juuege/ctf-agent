## 1. RSI 双环总览

- **记忆环（知识层）**：解题 `--write-trace` 留痕 → 写 writeup → `learn-writeup` 落库 → 下题 `recall` 检索。经验第一次出现是知识。
- **固化环（代码层）**：高频、可判定的经验编译为快通道确定性检测器/工具脚本。经验第二次出现就该是工具（对应 SpecPilot"记忆条目 → 新部署初始系统"，也对应 CTF 专家赛前固化的 quickcheck 脚本）。

防污染纪律（对应 SpecPilot 的 Token Forcing 与密封终测）：

- flag 未验证通过的结论不落库、不固化。
- 看图类结论必须经用户确认后才写成经验。
- 经验不适用时新写版本化条目，不删旧记录；固化脚本升级同理。
- lessons 按（category, technique, 来源指纹）upsert，recall 按 technique 去重——同技术反复成功只刷新时间戳（频率本身是信号），重复不挤占 top_k。
- 标签与"一得"必须来自实测证据（flag 验证/脚本输出），不许凭题面想象。
- 复用记忆/固化工具解出的题，收益不计入"新发现"。

## 2. 落库 writeup 模板

```markdown
# <题名> writeup
- 题型: misc / crypto / reverse / web / ...
- 题面特征: <一眼可辨的信号：魔数、文件名、大小、参数特征>
- 解题路径: <关键技术链，如 多音调MFSK → 双音调组合 → 窗口重组>
- 有效技术: <什么技术在什么条件下有效，附关键参数>
- 失败路径: <被否决的假设及其否决证据>
- 适用限制: <仅在什么条件下验证过>
- 未测试: <哪些边界没碰过>
- 标签: 识别信号=?；陷阱类型=?；可迁移模式=?(一句话规则)；变体预测=?
- 可固化性: 是/否；若是，附"特征检测条件 + 确定性判定逻辑"
```

## 3. 固化跃迁 SOP（六步）

1. **触发判定**：`recall` 同一技术被反复取用 / trace 同类 detector 反复 miss / 补位分析发现确定性特征。频率信号不足时只落库、不固化。
2. **写规格**："特征检测条件 + 确定性判定逻辑"——什么字节/字符集特征触发、判定规则、失败时自动降级行为。
3. **实现（≥2 候选对比）**：同一固化目标至少实现 2 种候选（如独立子命令 vs 挂检测器链 vs 改 triage 判定），同题计时 A/B 选最快；纯 Python 标准库优先，实测可用，单源失败自动降级不炸链；临时依赖装 `.temp` 勿动全局；放入 CTFPilot 工程合适目录。
4. **回归验证**：原题重放必须解出同一 flag；典型负样本（无该特征的题）不误报。
5. **密封终测**：`selftest` 6 道冒烟题全过才算固化上线。
6. **实战验证 + 版本化**：下一道同题型真题验证收益；不适用则升级脚本版本并更新 writeup，旧记录保留。

### 固化候选清单（纯标准库可实现，按性价比排序）

| 候选 | 要点 |
|---|---|
| 魔数表扩展 | PNG/JPEG/GIF/RAR/7z/PDF/ELF/PE 等 8-16 字节魔数匹配，提升 triage 精度 |
| ZIP 伪加密修复 | 本地头偏移 6 与中央目录偏移 8 处标志位 `&= 0xFE` 清理，纯 bytearray 操作 |
| PNG 宽高 CRC 校验 | `zlib.crc32(b'IHDR'+ihdr)` 与文件 CRC 比对，命中即"改宽高未改 CRC" |
| IDAT 解压量反推宽高 | 解压长度 ÷ 每像素字节数；CRC 被重算过时的第二抓手 |
| 编码特征识别扩展 | Base32/摩斯/培根/二进制转 ASCII 的字符集频率判断，与现有 b64/hex 检测同构 |
| 零宽字符检测 | `E2 80 8B/8C/8D`、`EF BB BF` 序列扫描，按出现顺序映射 0/1 |
| 尾部附加数据截取 | JPEG `FF D9` / PNG IEND 之后内容用 `rfind` 切出 |
| ZIP CRC 爆破 | `itertools.product` + `zlib.crc32`，≤4 字节搜索空间秒级 |

### 进化方式对比（同一经验选最快载体，实测后定）

| 载体 | 生效方式 | 预期解题提速 | 成本 |
|---|---|---|---|
| 固化工具/检测器 | 零思考直接命中 | 最大（秒级、确定性） | 实现+验证一次性 |
| 修 SKILL.md 触发器 | 改善路径选择 | 中（少走弯路） | 低 |
| 落库 writeup/recall | 供模型检索参考 | 小（仍需临场推理） | 最低 |

决策规则：同题 A/B 实测——「recall+模型按知识执行」vs「固化工具直接解」的耗时对比，差值大才固化，差值小只落库。

**边界**：像素级操作（LSB 提取、双图异或）纯标准库需手写 PNG 解码器，不划算——走 `.temp` 装 Pillow 或深通道补位。外部成熟工具优先于自研（大厂/社区已有 awesome-ctf 等清单可对标）。

## 4. 元认知复盘模板（每题后 30 秒）

| 步骤 | 耗时（估） | 瓶颈类型 | 修复动作 |
|---|---|---|---|
| 定位工程 / 解题 / 补位分析 / 查外部资料 / 反复试错 | ... | 引擎缺检测器 / skill 描述不清 / 临场才学 / 重复踩坑 | 固化脚本 / 修 SKILL.md / 落库 writeup / 无需动作 |

瓶颈 → 修复优先级：**固化脚本 > 修 SKILL.md 触发器 > 落库 writeup**。

- "临场才学外部知识"且知识可判定 → 优先固化（把学习成本一次性付清）；检索路径按 `references/ctfpilot-extsearch.md` 的实测基准选最快一条，不临场重新发明检索方案。
- "skill 描述不清导致走错路" → 当场修触发器，并把教训写成本节规则。
- "重复踩已知坑" → 检查为什么 recall/固化没生效：是没检索、检索了没用上、还是经验本身错。
- 输出自查：执行叙述与 writeup 是否超速度纪律预算（每步 ≤1 行、writeup ≤15 行、总结 ≤10 行），超了记录一行并在下次收敛。

## 5. skill 自审 checklist（修改 SKILL.md 前逐项过）

- [ ] 此修改能让下一题解得更快或让更多变种可解吗？（不能则不做）
- [ ] 是否只服务低频场景？→ 放 `references/`，主干只留一句话索引
- [ ] 是否引入歧义或过度复杂？→ 用具体命令示例替代抽象描述
- [ ] 主干是否逼近长度红线？→ 拆分外移，保持渐进式披露，防首 token 膨胀拖慢解题
- [ ] 修改后是否做了回归验证（原场景重放）+ `quick_validate.py` 校验 + 安全扫描？
- [ ] 是否对照过外部基准（大厂 skill 规范、awesome-ctf 等社区成熟做法），而非闭门造车？（检索路径与实测最快方案见 `references/ctfpilot-extsearch.md`）

## 6. 标签体系与举一反三（每题必打）

每道题（成功或失败）按固定维度打标，写入 writeup 对应字段：

| 维度 | 取值示例 | 作用 |
|---|---|---|
| 题型 | misc / crypto / ... | recall 一级过滤 |
| 载体/格式 | cf32 无头 / png / pcap | 识别信号匹配 |
| 识别信号 | 相位 0/π 跳变；魔数缺损；命名暗示 | 相似题一眼命中 |
| 核心技术链 | BPSK→Viterbi→CRC16 | 直接复用链路 |
| 陷阱类型 | 位序反转；CRC 覆盖范围；循环窗口误判 | 提前避坑 |
| 可迁移模式 | "相位跳变间隔 = SPS" 一句话规则 | 举一反三的最小单元 |
| 变体预测 | 换 QPSK？加扰码层？换帧长？ | 预判变形，扩大覆盖 |

**举一反三检验**：解出后自问"这题若变形（换编码层/加一层加密/换载体），流程还能解吗？"把答案写进"变体预测"；同类变体下次出现时先查标签再动手。

**模式卡**：每题至少产出一条"可迁移模式"（识别条件→技术组合的一句话规则），learn-writeup 时并入 technique/when_to_use，使其可被 recall 检索。

## 7. 框架级进化（A/B 测试，防自嗨）

优化的对象不只是题库，还有解题框架本身（工作流顺序、知识预热方式、搜索时机、补位策略）。

**指标（唯一标准）**：保留题集平均解题时长 + 正确率。题库大小、writeup 数量都不是指标。

**流程**：
1. 维护保留题集：换新题或变体题，≥3 道，未参与过任何 learn/固化。
2. 基线跑：当前 SKILL.md 流程 × 保留题集 → 记录 (时长, 正确率, 工具调用数)。
3. 候选跑：只改一个变量（如"知识预热从 recall 改为标签优先"）→ 同题集重跑。
4. 判定：时长降 ≥15% 或正确率升且时长不升 → 赢家写入 SKILL.md，注明回滚点（改动前版本存档）。
5. 触发时机：每 5 道新题或连续失败 2 道，避免过度优化。

**搜索人类框架**：做框架实验前，先按 `ctfpilot-extsearch.md` 检索人类解题手框架与 agent 推理框架（ReAct / plan-and-solve / checklist triage / hypothesis loop），候选变量优先从这些成熟框架借。
