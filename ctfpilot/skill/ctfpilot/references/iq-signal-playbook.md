# 信号/IQ 类 CTF 补位分析 playbook

适用：附件是 `.iq/.bin/.raw/.cf32` 等无头文件，或题目描述涉及卫星、SDR、无人机、遥测、调制识别。引擎（纯标准库、无 DSP）必然 miss，直接走本 playbook。

## 0. 先办学，再动手

优先检索"赛事名 + 题名 + 附件名"的公开 writeup（如数信杯、强网杯、DEFCON 等）。很多信号题是"自描述"设计，题解会直接给出链路参数。找到 writeup 就先把参数抄下来，再用自己的脚本复现验证，不要从零盲猜调制。

## 1. 三分钟定性（不要一上来就做谱分析）

按顺序做三件事，全部脚本打证据：

1. **魔数与采样格式**：文件大小 / 4 = complex64 点数；/8 = complex128；偶数且包络恒模 → 先按 CF32 处理。
2. **采样级相位**：打印前 200~400 点 `angle(x)` 或 `x.real`。若相位只在 0/π 两值跳、且每 N 点翻转一次 → **BPSK，SPS=N**（本题 N=64）。这一步比频谱快十倍且不会误判。
   - 脉冲成形下逐点相位噪声可达 ±40°，肉眼易误判：改用**符号中心相位差直方图**——对每个候选 SPS 取符号中心点求相邻相位差，直方图集中落在 π 附近且间隔=N 的即为真值（实测 61/63 命中）；不要只看 angle 曲线。
3. **包络与频谱**：`mean(|x|)` 是否恒定；FFT 是否有 `fs/128` 奇次倍离散谱线（这是方波副载波特征，**不是**多音调 MFSK）。

反面教训：曾把 BPSK 误判为"5 音调 MFSK + 2-of-5 双音调 + 循环重叠读段"，连续 19 个阶段全错。根因是跳过采样级观察、直接对频谱做音调分类，把方波谐波当成了多音符号。

## 2. 找自描述引导头（最高优先级）

现代竞赛信号题常带**明文自描述引导头**（self-describing bootstrap），把 FS/SPS/MOD/CFO/同步字/编码/交织/扰码/帧格式全写在里面。做法：

```python
bits = (x.real.reshape(-1, SPS).sum(axis=1) < 0).astype(int)
hdr = bytes(np.packbits(bits))
p = hdr.find(b"SPACECTF")   # 或 b"CTF" / b"BOOT" / b"SAT"
```

- SPS 不知道就暴力试 8/16/32/64/128/256，看哪个能出可打印 ASCII。
- 极性/位序（invert、LSB-first）用"模板匹配字节数"做目标函数自校准。
- 引导头通常重复 2~3 遍，可用重复段做自校验。

## 3. 参数直接读，不要盲扫

引导头里的 `CFO=+200HZ;FS=1024000` 直接算 `fc = 200/1024000`，精度远高于盲扫。盲扫只在没引导头时用，且必须用**尖锐**目标函数（星座沿 I 轴锐度），不要用"出现次数"这种平台型目标（会在 196~256Hz 之间乱跳）。

没有引导头数值可读时：FFT 估 CFO 的分辨率受 bin=fs/N 限制（实测 31.25Hz 不够用，残余会把数千符号后的判决极性带翻）——先 FFT 粗估，再用**判决引导迭代**精估（解调→按判决重采校正→再解调，2~3 轮收敛到 0.1Hz 级）。

## 4. 信道译码的位序陷阱（本题真正卡点）

- **卷积码生成多项式位序**：`0o171` 表示 `g(x)=1+x^3+x^4+x^5+x^6`。若实现是"新输入放最高位、状态右移"（`reg=(inp<<6)|state`），掩码必须用**位反转** `rev7(0o171)=0b1001111`；直接用 `0b1111001` 会译出噪声。等价做法：新输入放最低位、状态左移，则直接用 `0o171`。两种约定必须与编码端一致。
- **自测方法**：用随机已知消息 → 按假设编码 → 按假设译码 → 要求 100% 还原（含尾零）。自测不过就是约定错了，别去调交织和极性。
- **扰码器不动点**：`x^8+x^7+x^2+x+1` 初值 0xFF 是不动点，PN 恒全 1，扰码退化为整体取反 → "解扰"就是再取反一次。不要过度实现 LFSR。
- **交织方向**：`5X5-ROW-WRITE-COL-READ` → 解交织 = 每 25 位块 `reshape(5,5).T.ravel()`。
- **CRC 覆盖范围**：可能是"LEN 字节 + 正文"而不是仅正文。CRC 对不上时先换覆盖范围，再怀疑译码链。
- **帧尾与帧长算术**：载荷尾可能是 EOT(0x04) 结束符；帧长从编码比特数反推——编码比特 = 2×(信息比特 + 尾零 6)，对不上先查这个再查交织。

## 5. 验证顺序（每次只改一个变量）

1. 引导头明文可读 → 解调/CFO 正确。
2. 同步字（如 1ACFFC1D）在预期位置 → 位对齐正确。
3. 帧长度字节合理（如 214）→ 译码链基本正确。
4. CRC 匹配 → 全链正确。
5. 正文可读 → 提 flag。

任何一步不过，只回退该步对应的变量，不要同时改极性+交织+G 顺序（会组合爆炸且无法归因）。
